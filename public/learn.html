01

Tour the built-in families

Files: Read, Edit and Write. Search: Glob and Grep. Execution: Bash. Web: WebFetch and WebSearch. The live app focuses on local files, search and a fixed classroom test command.

02

Separate availability from approval

tools chooses built-ins in context. allowedTools pre-approves matching calls; it does not remove unlisted tools. A bare disallowedTools name removes a tool, while a scoped deny rule leaves it visible.

03

Observe searches and a real repair

Compare Glob, Grep and Read with an Edit, a Write and npm test. Independent host tests verify failure before the repair and success afterward. Original lesson fixtures remain unchanged.

04

Compare scoped rules and callbacks

Bash(npm test) pre-approves that command. An unlisted extra script reaches the denying callback. Bash(npm run extra) is a scoped deny; compare attempted calls, completed tools and side effects.

05

Protect a fake environment file

Read(./.env) applies to a dummy file in the private project. The real app .env is outside that project. Record whether the model attempts the Read or refuses in advance; do not invent an attempted denial.

06

Inspect MCP-only availability

With tools: [], built-ins are absent while the configured classroom MCP tool remains. One actual in-process call proves this distinction. Orchestration tools and web tools are reference topics for later lessons.
